# Distortion Labs

Marketing site for [Distortion Labs](https://distortion-labs.com), built with Next.js (App Router) and deployed on Vercel.

**Stack:** Next.js 16 · React 19 · TypeScript · Tailwind CSS 3 · Framer Motion · React Three Fiber (WebGL hero) · Vercel Analytics

## Getting started

Requires Node.js 20.9 or newer.

```bash
npm install
npm run dev        # http://localhost:3000
```

| Script              | What it does                                  |
| ------------------- | --------------------------------------------- |
| `npm run dev`       | Start the dev server (Turbopack)              |
| `npm run build`     | Production build (includes type checking)     |
| `npm run start`     | Serve the production build                    |
| `npm run lint`      | ESLint                                        |
| `npm run typecheck` | Generate route types and run `tsc --noEmit`   |

## Pages

| Route                    | Description                                         |
| ------------------------ | --------------------------------------------------- |
| `/`                      | Home — hero, featured products, about teaser, CTA   |
| `/products`              | All products                                        |
| `/products/[slug]`       | Product detail page, one per entry in `lib/products.ts` |
| `/about`                 | Story, principles, focus areas, tech stack          |
| `/contact`               | Contact form (or email fallback, see below)         |
| `/privacy`               | Privacy policy                                      |
| `/email-verified`        | Standalone confirmation page for email verification links (not indexed) |

SEO and metadata are generated by Next.js file conventions in `app/`: `sitemap.ts`, `robots.ts`, `manifest.ts`, `opengraph-image.tsx` (share image) and the `icon.png` / `apple-icon.png` / `favicon.ico` icons.

## Project structure

```
app/
  (site)/            Pages that share the header + footer layout
    contact/         Contact page, form (client) and server action
    products/[slug]/ Statically generated product pages
  email-verified/    Standalone page without the site chrome
  layout.tsx         Root layout: fonts, default metadata, analytics
components/          UI sections and building blocks
lib/
  site.ts            Site name, URL, email, social links, navigation
  products.ts        Product catalogue (drives /products, detail pages and sitemap)
  metadata.ts        Per-page metadata helper
  contact.ts         Contact form configuration
```

Most content edits happen in `lib/site.ts` and `lib/products.ts`. To add a product, add an entry to `products` — its page, sitemap entry and listing card are created automatically.

## Deploying to Vercel

1. Go to [vercel.com/new](https://vercel.com/new) and import this GitHub repository. The Next.js framework preset is detected automatically; no build settings need changing.
2. Add any environment variables (below) under **Project → Settings → Environment Variables**.
3. Deploy. Every push to `main` deploys to production and every pull request gets a preview URL.

### Moving the custom domain from GitHub Pages

The site previously deployed to GitHub Pages. To switch `distortion-labs.com` over:

1. In Vercel, open **Project → Settings → Domains** and add `distortion-labs.com` (and `www.distortion-labs.com` if you use it).
2. Update the DNS records at your registrar to the values Vercel shows on that page.
3. Once the domain verifies on Vercel, disable GitHub Pages under the repository's **Settings → Pages**.

### Analytics

`@vercel/analytics` is already wired into the root layout. Turn it on under **Project → Analytics** in the Vercel dashboard.

## Environment variables

See [`.env.example`](.env.example). All are optional.

| Variable               | Purpose                                                                 |
| ---------------------- | ----------------------------------------------------------------------- |
| `NEXT_PUBLIC_SITE_URL` | Canonical origin for metadata and the sitemap. Defaults to `https://distortion-labs.com`. |
| `RESEND_API_KEY`       | [Resend](https://resend.com) API key used to deliver contact form messages. |
| `CONTACT_FROM_EMAIL`   | Sender address, e.g. `Distortion Labs <noreply@distortion-labs.com>`. Its domain must be verified in Resend. |
| `CONTACT_TO_EMAIL`     | Inbox that receives messages. Defaults to `contact@distortion-labs.com`. |

### Contact form

The contact form is enabled only when both `RESEND_API_KEY` and `CONTACT_FROM_EMAIL` are set; otherwise `/contact` shows email links instead. Because the page is statically generated, redeploy after changing these variables. Submissions are validated on the server, include a honeypot field for basic bot filtering, and set the visitor's address as `reply_to` so you can answer directly from your inbox.

## CI

`.github/workflows/ci.yml` runs lint and a production build on pushes to `main` and on pull requests. Deployments themselves are handled by Vercel's Git integration.
